OVERVIEW

개요

코드리뷰는 받고 나면 흩어집니다. 같은 지적을 몇 번째 받는지 세어 주는 곳이 없습니다.
COGI는 GitHub 웹훅으로 PR을 받아 AI가 리뷰하고, 모인 약점은 학습 카드와 퀴즈로 만들어 다시 풀게 합니다.
저는 4인 팀의 팀장으로 학습·리텐션 도메인과 AI 벤더 연동을 맡았습니다.
인증·스튜디오·성장 화면은 Claude·Gemini로 시안과 컴포넌트를 만들어 붙이며 프론트 작업 시간을 줄였고, 그만큼을 백엔드 설계에 썼습니다.

03 · DEVELOPMENT

개발 — 문제 해결 과정

실제 커밋 이력에 남은 트러블슈팅을 발견 → 원인 → 해결 순으로 정리했습니다.
대부분 "될 때도 있고 안 될 때도 있다"로만 보이던 증상이라 원인을 가르는 데 시간이 더 걸렸습니다.

① 약점 통계를 두 화면이 동시에 열면 500
발견

약점 화면과 스킬 추천 화면이 같이 뜨거나
StrictMode가 이펙트를 두 번 실행하면 500이 났습니다.

원인

조회 API가 매번 deleteByUserId 후 재삽입을 했습니다. 뒤 트랜잭션이 앞에서 이미 지운 행을 지우려 들었습니다.

해결

표에 쓰지 않고 getWeaknessStats()에서
조회 시점에 집계해 바로 응답으로 만들었습니다.
그 표를 읽는 코드가 없어 쓰기를 걷어냈습니다.

fix: 약점 통계 재집계 동시 호출 시 500 · fix: 약점·강의·스킬추천 500과 PR 피커가 실제 레포를 못 보던 것
② 퀴즈 생성이 될 때도 있고 안 될 때도 있었다
발견

같은 카드인데 어떤 퀴즈는 만들어지고
어떤 퀴즈는 파싱에서 터졌습니다.

원인

둘이었습니다. 프롬프트가 문제 본문에 코드블록을 넣게 지시하는데 모델이 줄바꿈을 그대로 흘려 JSON이 깨졌습니다. 스키마에 없는 키가 하나 붙어도 통째로 실패했습니다.

해결

AI 응답 전용 리더를 따로 두고
ALLOW_UNESCAPED_CONTROL_CHARS를 켜고
FAIL_ON_UNKNOWN_PROPERTIES를 껐습니다. 공용 ObjectMapper는 API 직렬화에도 쓰여 건드리지 않았습니다.

fix: 문제 생성이 될 때도 있고 안 될 때도 있던 원인
③ AI가 응답하지 않으면 화면이 계속 "분석 중"이었다
발견

벤더가 503을 뱉고 재시도하는 동안
스튜디오가 "코드 분석 중…"에서 멈추지 않았습니다.

원인

RestClient.builder().build()가 이 프로젝트에서 JdkClientHttpRequestFactory로 폴백되는데 기본 생성자에는 연결·응답 타임아웃이 아예 없었습니다.

해결

연결 10초 · 응답 60초를 명시하고
실패는 AI_MODEL_CALL_FAILED로 올려
화면이 끝을 보게 했습니다.

fix: 빌드 깨짐과 AI 호출 실패 무반응 수정
④ 벤더마다 요청·응답 규격이 어긋났다
발견

모델을 실제로 붙이자 400과
빈 응답이 섞여 나왔습니다.

원인

OpenAI 신형 모델에서는 max_tokens가 통하지 않고 max_completion_tokens를 써야 했습니다. Claude는 확장 사고를 쓰면 content[0]이 thinking 블록이라 텍스트가 비었습니다. 이슈가 많은 리뷰는 JSON이 중간에 잘렸습니다.

해결

호출 경로를 callOpenAiCompatible()과
callAnthropic()으로 갈랐습니다.
content 배열에서 text 블록을 찾아 꺼내고
최대 토큰을 8192로 올렸습니다.

fix: AI 모델 실제 API 연동 시 발생하는 파싱/파라미터 오류 수정 · feat: AI 모델별 provider 라우팅 구조 분리 (AiProvider/AiModel)
⑤ DB를 새로 심어도 화면은 옛 정보를 믿었다
발견

데이터를 초기화한 뒤에도 화면은 GitHub이 연동된 줄 알고 요청을 보내 400을 받았습니다.

원인

AuthContext가 localStorage 캐시를
끝까지 신뢰했습니다.

해결

새로고침마다 서버 프로필로 캐시를 맞추고
화면 표시용 값만 남겨 덮게 했습니다.
쿠키가 죽은 경우는 401을 보고 로그아웃시킵니다.

fix: 캐시된 로그인 정보가 서버와 어긋나던 것 + 미처리 실패 4곳 · fix: DB를 새로 심어도 코기와 학습 기록이 그대로이던 것
MY PART

담당 파트 (정상연)

01

AI 벤더 연동 (global/ai)

  • AiProvider·AiModel로 호출 방식과 단가를 분리
  • 타임아웃·코드펜스·스키마 방어를 클라이언트 한 곳에 모음
02

약점 통계 (learning)

  • 카테고리·언어로 묶어 3회 이상만 집계
  • 의도한 코드로 처리한 지적은 집계에서 제외
03

학습카드 · 퀴즈 (learning)

  • 카드·퀴즈·학습 계획 생성과 승급 히스토리
  • 크레딧 선차감, 파싱 실패 시 롤백으로 복구
04

AI 스킬 추천 (learning)

  • 약점 기반·자유 입력 두 경로를 같은 스키마로 통일
  • 생성 결과를 내 소유 행으로 남겨 즐겨찾기와 연결
05

리텐션 (retention)

  • 제출 기준 streak과 누적 학습일 집계
  • 달력은 따로 저장하지 않고 제출 이력에서 유도
06

프론트엔드 (AI 활용)

  • 인증(로그인·회원가입·OAuth 콜백·온보딩·2FA) 화면
  • 스튜디오·학습·성장 화면과 모바일 전용 화면 15개
  • Claude·Gemini·Figma로 시안·컴포넌트를 뽑고 API 연동은 직접
